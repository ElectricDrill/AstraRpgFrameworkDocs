Describes how a single CompositeStep<TContext> relates to the steps around it while a CompositeGameAction<TContext> walks its step list.

public enum CompositeStepMode

Fields

Await = 0

Start the step, add it to the open group, then wait for the entire group (every step started since the last Await) to finish before moving to the next step. This is the default and reproduces the classic "run actions one after another" behaviour.

FireAndForget = 2

Detach the step onto the owner's GameActionRunner via RunFireAndForget(TContext, MonoBehaviour). It never joins the open group and is never awaited, and — because it runs on the runner — it does not inherit the parent composite's System.Threading.CancellationToken; it is instead bound to the owner GameObject's lifetime. Requires a runtime owner (or a context that is itself a MonoBehaviour); otherwise the step is skipped with a warning.

InParallelWithNext = 1

Start the step, add its awaitable to the open group, and continue to the next step in the same frame without waiting. The group is awaited later, either by the next Await step or when the step list ends.

Remarks

The composite keeps a single "open group" of in-flight awaitables while it iterates. InParallelWithNext adds the step to that group and moves on; Await adds the step and then waits for the whole group to finish before continuing. So InParallelWithNext, InParallelWithNext, Await starts three steps in the same frame and resumes only once all three have completed.
